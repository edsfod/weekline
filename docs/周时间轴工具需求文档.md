# 周时间轴工具需求文档

Sep 25, 2026（2026-09-25 修订：三级模板与具体日子、配色、改为本地网页服务，见第 11 节）

## 1 概述

本文档规定一个在电脑浏览器中使用的时间轴编辑工具的需求。工具由本机的一个小型网页服务和它送出的页面组成（NFR-1）。该工具把手绘的“模板日加一周安排”时间轴数字化，以半小时为单位编辑区间，并与 md 文本互相转换。安排分三个抽象级：唯一模板、周模板、具体日子，下级的默认内容继承上级。

### 1.1 目的

工具用于制定和修改时间安排：先定一个模板日，再定一周七天各自的模板，最后落到具体的日子。它表示安排的内容，并执行由数据模型本身推出的规则；它不对安排做统计或评价。

### 1.2 范围

工具包含：
- **模板页**：一个唯一模板和七个周模板。
- **日程页**：从起始日到“当前日期所在周的下一个完整周”的全部具体日子，以及参照行（唯一模板，和选中那天所属星期的周模板）。
- **其他**：一个 md 文本视图（笔记也在其中修改），以及计划文件的自动保存、导入与导出。

统计功能、实际执行情况的记录等内容不在本版本范围内，完整列表见第 10 节。

### 1.3 依据材料

本文档的依据有五项：
1. 两张手绘图，一张是模板日，另一张是周一至周五的安排。
2. md 文件《活动-休止结构》。
3. 需求讨论中确认的决定，包括：
   - 以半小时为单位；
   - 圈注表示外部固定安排；
   - 允许显然的规则；
   - 2026-09-25 修订时确认的：三个抽象级、继承规则、参照行、一周起始可选。
4. 界面配色约定（作者的本地资料，下称“配色约定”）。
5. 界面约定（作者的本地资料，下称“界面约定”），包括字体与字号、形状、显示设置、本机硬件参数、后台运行；以及实现这些约定的公共模块 web-kit（https://github.com/edsfod/web-kit ）。

### 1.4 文档约定

功能需求编号为 FR-节号.序号，非功能需求编号为 NFR-序号，验收条件编号为 AC-序号，数据不变式编号为 I-序号。修订时编号保持稳定：取消的条目保留编号并注明“已取消”，新增条目接在该节已有编号之后。

“必须”表示实现不满足该条即不合格。“应当”表示推荐做法，实现偏离时必须说明理由。“可以”表示可选功能。

文中的时刻一律采用 24 小时制，写作 HH:MM；日期写作 YYYY-MM-DD。区间一律按左闭右开理解，即 08:00–12:00 包含 08:00 所在的格，不包含 12:00 所在的格。

## 2 术语

下表中的术语在本文档中只按此处的定义使用。

| 术语 | 定义 |
| --- | --- |
| 格 | 长度为 30 分钟的时间单位，起点在整点或半点。格是工具中时间的最小单位。 |
| 显示范围 | 所有行共同显示的一天之内的时间段，由起点和终点两个时刻确定，默认为 07:00–22:30，共 31 格。 |
| 安排对象 | 一天的安排，由若干区间组成。安排对象分三个抽象级：唯一模板、周模板、具体日子。三个抽象级的安排对象都是实体，各自拥有自己的区间。 |
| 唯一模板 | 最上级的安排对象，全文档只有一个，表示默认的一天。 |
| 周模板 | 第二级的安排对象，共七个，分别对应周日至周六，表示一周中某一天的默认安排。它的上级是唯一模板。 |
| 具体日子 | 最下级的安排对象，对应日历上的某一天。它的上级是与它星期相同的那个周模板。 |
| 上级 | 周模板的上级是唯一模板；具体日子的上级是同一星期的周模板。唯一模板没有上级。 |
| 跟随 | 周模板和具体日子的一种状态：它的内容等于上级当前的内容，上级改变时随之改变。新出现的周模板和具体日子都处于跟随状态。 |
| 已编辑 | 周模板和具体日子的另一种状态：它有自己的区间，不再随上级改变。唯一模板总是已编辑的。 |
| 一周起始日 | 一周从星期几开始，可选，默认为周日。它决定模板页中周模板的排列顺序、日程页的按周分组，以及加载范围的终点。 |
| 起始日 | 日程页从哪一天开始，由用户选定。 |
| 加载范围 | 日程页显示的具体日子的范围：从起始日到当前日期所在周的下一个完整周的最后一天（周按一周起始日划分）。 |
| 行 | 一条水平时间轴，由显示范围内的全部格组成，显示一个安排对象的内容。 |
| 可编辑行 | 在当前页中可以编辑的行：模板页的唯一模板行和七个周模板行；日程页的具体日子行。 |
| 参照行 | 日程页中显示上级安排对象的只读行，包括固定在顶部的唯一模板参照行，以及选中某个具体日子时在它下方显示的周模板参照行（FR-5.24）。 |
| 模板页 | 编辑唯一模板和周模板的页面。 |
| 日程页 | 编辑具体日子的页面。 |
| 区间 | 某一行中由连续若干格组成的时间段，是工具中唯一的安排对象内容。一个区间表示一个已包装的活动-休止结构，工具不表示其内部组成。 |
| 类别 | 区间的属性，取值为“外部固定安排”“自主安排”“日常事务”之一。外部固定安排对应手绘图中圈起来的标注，例如上课；日常事务指吃饭、洗漱这类每天都有的事。 |
| 文字 | 区间的可选短文本，例如“上课”“家务”。 |
| 浮动 | 区间的布尔属性。工具只显示这一属性，不赋予它任何行为。 |
| 笔记 | 不属于任何区间的多行自由文本，全文档只有一处，写在计划文件最后的“## 笔记”一节。页面上没有单独的笔记区，笔记只在文本视图（或直接在计划文件）中修改。 |
| 计划文档 | 一份完整的数据，包括标题、显示范围、一周起始日、起始日、唯一模板、周模板、具体日子和笔记，对应一个 md 文件。（原称“周文档”。） |
| 计划文件 | 工具读写的那一个 md 文件，存放计划文档的规范文本，位置见 FR-7.13。 |
| 服务 | 在本机运行、只供本机浏览器访问的网页服务。它送出页面，并替页面读写计划文件。 |
| 时刻事件 | 没有时长、只标一个时刻的事，例如起床、睡觉。它只能在文本中书写（计划文件或文本视图），编辑区只显示它，不能选中或修改，见 3.5 节。 |
| 格选区 | 用户选中的一组格，形状为“若干可编辑行乘以一段连续时间”的矩形。 |
| 锚点 | 格选区中固定不动的那一格：拖动选择时按下鼠标的那一格，单击时被单击的那一格。它记住选区是从哪一头选起的：Shift 加方向键、Shift 加单击调整选区时，锚点不动、另一头移动，所以同一个按键既能加长也能缩短选区；方向键、Space 和上下文菜单里的行操作也以锚点为准（6.2 节、FR-6.3、FR-6.9）。粘贴不看锚点，从选区的左上格开始（FR-6.15）。锚点的显示见 FR-5.17。 |
| 区间选区 | 用户选中的一个或多个区间。 |
| 写入类操作 | 以格选区为目标、在其中产生或清除区间的操作，包括设为区间、清除、粘贴。 |
| 移动类操作 | 改变已有区间位置或端点的操作，包括平移和调整端点。 |

## 3 数据模型

数据模型由计划文档、安排对象、区间三种实体组成。
- 时刻以“自 00:00 起的分钟数”存储为整数，取值必须是 30 的整数倍，范围为 0 至 1440。
- 星期以 0 至 6 表示，依次为周日至周六。

### 3.1 计划文档

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| title | 字符串 | 非空，不含换行，长度不超过 100 个字符。默认值为“本周时间安排”。 |
| range.start | 整数（分钟） | 30 的整数倍，不小于 0。默认值为 420（07:00）。 |
| range.end | 整数（分钟） | 30 的整数倍，不大于 1440，且至少比 range.start 大 60。默认值为 1350（22:30）。 |
| weekStart | 整数（星期） | 0 至 6。默认值为 0（周日）。 |
| startDate | 日期 | 不晚于加载范围的最后一天。新建时默认为当前日期所在周的第一天。 |
| base | 安排对象 | 唯一模板。 |
| weekly | 安排对象的数组 | 长度恰为 7，下标为星期（0 为周日）。 |
| days | 从日期到安排对象的映射 | 只包含已编辑的具体日子；没有记录的日子处于跟随状态。可以包含加载范围之外的日子，它们保留但不显示。 |
| note | 字符串 | 可以为空，可以包含换行。 |

### 3.2 安排对象

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| follow | 布尔 | 为 true 表示跟随，为 false 表示已编辑。唯一模板恒为 false。 |
| intervals | 区间的数组 | follow 为 true 时为空；否则按 start 升序排列，满足 I-3。 |
| events | 时刻事件的数组 | follow 为 true 时为空；否则按时刻升序排列，见 3.5 节。 |

安排对象的**有效内容**定义如下：
- follow 为 false 时，是它自己的 intervals 和 events；
- follow 为 true 时，是它上级的有效内容。

界面显示、复制、文本视图中列出的都是有效内容。

### 3.3 区间

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| id | 字符串 | 在整个计划文档内唯一。id 只在运行时使用，不写入 md 文本。 |
| start | 整数（分钟） | 满足 I-1、I-2。 |
| end | 整数（分钟） | 满足 I-1、I-2。 |
| kind | 枚举 | 取值为 external（外部固定安排）、self（自主安排）或 daily（日常事务）。新建区间的默认值为 self。 |
| text | 字符串 | 可以为空；不含换行、“\[”“\]”“\~”和全角“～”（“\~”在文本中表示浮动，见 7.1 节）；首尾没有空白；不能整段用圆括号括起来，即不能以“(”或“（”开头同时以“)”或“）”结尾（这样的写法在文本中表示日常事务，见 7.1 节）；长度不超过 40 个字符。浮动区间的文字不能是“浮动”：文字为空的浮动区间显示的就是“浮动”（FR-5.13），设为“浮动”时按空处理。 |
| float | 布尔 | 默认值为 false。 |

区间的时长不作为字段存储，一律由 end − start 计算。

### 3.4 不变式

工具在任何操作完成后都必须保持以下不变式成立。违反不变式的操作必须整体不生效，见 FR-4.2。

- **I-1** 每个区间的 start 和 end 都是 30 的整数倍。
- **I-2** 每个区间满足 range.start ≤ start < end ≤ range.end。
- **I-3** 同一安排对象中任意两个区间不重叠，即对任意两个区间 a、b，有 a.end ≤ b.start 或 b.end ≤ a.start。首尾相接的两个区间不算重叠。
- **I-4** 同一安排对象中的区间按 start 升序排列。
- **I-5** 任何两个安排对象之间不共享区间对象。修改其中一个的区间不会改变另一个的区间；跟随的安排对象的内容变化只来自其上级的变化。
- **I-6** 处于跟随状态的安排对象没有自己的区间。
- **I-7** days 中每个日期至多出现一次，且都是合法的日历日期。

### 3.5 时刻事件

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| t | 整数（分钟） | 30 的整数倍，满足 range.start ≤ t ≤ range.end（可以恰好在显示范围的两端）。 |
| text | 字符串 | 不能为空；其余同 3.3 节区间文字的约束。 |

- 时刻事件不占时间，与区间之间没有冲突：它可以落在区间内部或区间的端点上，同一时刻也可以有多个时刻事件。
- 时刻事件只能在文本中书写（7.1 节）。编辑区的操作都不增删、不改动时刻事件，例外见 FR-4.8、FR-4.12。
- **起床与就寝**：文字恰为“起床”的时刻事件是该安排对象的起床时刻；文字恰为“睡觉”或“就寝”的是就寝时刻。每个安排对象至多有一个起床时刻和一个就寝时刻。
- **起床、就寝单独继承**，不跟区间和其他时刻事件走：一行的有效起床时刻是它自己的起床时刻；它没有（跟随状态，或已编辑但没写起床）时，取上级的有效起床时刻。就寝同理，两者互不影响。每一行的有效起床时刻和有效就寝时刻都有时，起床必须早于就寝。显示见 FR-5.31。

## 4 规则与约束

工具只执行由数据模型本身推出的规则。表达计划判断的内容（例如每日最高工作时长）属于笔记，工具不执行。

### 4.1 对齐与不重叠

- **FR-4.1** 所有操作产生的区间端点必须满足 I-1。鼠标指针位置换算为时刻时，必须取指针所在的格，不做四舍五入。
- **FR-4.2** 任何操作如果会使 I-1 至 I-7 中的任一条不成立，必须整体不生效，数据保持操作前的状态，并在状态栏说明冲突所在的行和时间段。
- **FR-4.3** 同一行中首尾相接且属性完全相同的两个区间必须保持为两个区间，工具不得自动合并它们。

### 4.2 写入类操作与移动类操作的冲突处理

两类操作对“目标位置已有区间”采用不同的处理方式：
- 写入类操作的目标格是用户明确选中的，选中本身就表达了替换这些格中原有内容的意图。
- 移动类操作的目标格没有被用户选中，因此工具不能替用户删除那里的内容。

- **FR-4.4** 写入类操作采用覆盖处理。对格选区中的每一行：
  - 完全落在选中时间段内的已有区间被删除；
  - 部分落在选中时间段内的已有区间被截去重叠部分；
  - 如果截去后剩下两段，这两段成为两个区间，各自保留原区间的类别、文字和浮动属性，并分配新的 id。
- **FR-4.5** 移动类操作采用拒绝处理。如果操作后的区间与同一行的其他区间重叠，或超出显示范围，按 FR-4.2 处理。

### 4.3 时长

- **FR-4.6** 区间的时长必须由 end − start 计算，以小时为单位显示，最多保留一位小数，末尾不补零，后接“h”。例如 240 分钟显示为“4h”，270 分钟显示为“4.5h”，30 分钟显示为“0.5h”。

### 4.4 继承

- **FR-4.7** 跟随的安排对象显示的内容必须等于其上级当前的有效内容。上级改变后，所有直接或间接跟随它的安排对象必须随之改变，包括日期已经过去的具体日子。
- **FR-4.8** 对一个跟随的安排对象执行任何使其内容发生变化的操作时：
  1. 先把它变为已编辑，并把上级当前的有效内容复制为它自己的区间和时刻事件（区间分配新的 id；起床、就寝不复制，它们单独继承，见 3.5 节）；
  2. 再对这份副本执行该操作。

  这两步合为一个撤销步骤。不使内容发生变化的操作（例如在空白处清除）不改变它的状态。在跟随的行中选中区间时，选中的是这一行显示的区间，对它们的操作按本条作用于这一行，不影响上级。
- **FR-4.9** 已编辑的安排对象不随上级改变。修改下级不会改变上级。
- **FR-4.12** 周模板和具体日子必须提供“重置为模板”：丢弃它自己的区间和时刻事件，恢复为跟随状态。该操作可以撤销。
- **FR-4.13** 每一行的行头必须标明该安排对象处于跟随状态还是已编辑状态，且不能只靠颜色区分（见 NFR-3）。区间本身的画法不因状态而不同。

### 4.5 显示范围

- **FR-4.10** 修改显示范围时，如果任何安排对象（包括加载范围之外保留的具体日子）的区间或时刻事件会落在新范围之外，修改必须不生效，并列出它们所在的安排对象和时间段或时刻。

### 4.6 操作的原子性

- **FR-4.11** 用户的每一次操作必须作为一个整体生效或不生效，并且作为一个撤销步骤。这包括：一次作用于多行的写入类操作、一次粘贴、一次重置为模板，以及 FR-4.8 中的变为已编辑连同随后的修改。

### 4.7 日期与加载范围

- **FR-4.14** 加载范围的终点必须按打开工具时的当前日期计算：找到当前日期所在的周（按一周起始日划分），再取下一周的最后一天。工具保持打开跨过零点时，应当重新计算。
- **FR-4.15** 起始日可以修改，但不得晚于加载范围的最后一天：
  - 改早：新进入范围的日子处于跟随状态；
  - 改晚：落到范围之外的已编辑日子保留在计划文档中，只是不显示。
- **FR-4.16** 修改一周起始日时，周模板的排列顺序、日程页的分组和加载范围的终点随之改变，任何安排对象的内容都不改变。
- **FR-4.17** 修改显示范围、一周起始日、起始日都会改变计划文档，都必须可以撤销。

## 5 界面布局

页面自上而下由顶栏、编辑区、状态栏组成，另有一个可显示或隐藏的文本视图。编辑区显示模板页或日程页之一。页面上不显示任何统计信息。

### 5.1 顶栏

- **FR-5.1** 顶栏必须包含以下内容：
  - 可编辑的标题；
  - 计划文件的文件名；鼠标悬停时显示完整路径，单击时提供“在资源管理器中显示”；
  - 保存状态（FR-5.2）；
  - “模板”“日程”两个页面切换按钮，当前页必须标出；
  - “导入”“导出”“撤销”“重做”“文本视图”“文档设置”六个按钮；
  - “显示设置”按钮和深浅切换按钮（NFR-6）。
- **FR-5.2** 保存状态必须如实反映计划文件与当前计划文档是否一致，取以下之一：
  - “已保存”：计划文件的内容等于当前计划文档的规范文本；
  - “保存中”：有修改尚未写入计划文件；
  - “保存失败”：最近一次写入失败，必须写明原因（例如服务已停止），并说明工具会在服务恢复后自动重试；
  - “文件在别处被修改”：见 FR-7.15。

  后两种必须醒目，不能只靠颜色区分。

### 5.2 编辑区的共同规定

- **FR-5.4** 时间标尺必须固定在编辑区顶部：编辑区垂直滚动时始终可见。各页另有固定在顶部的行，见 5.3 节、5.4 节。
- **FR-5.5** 每一行由左侧行头和右侧轨道组成。行头显示行名和状态（FR-4.13），水平滚动时行头必须保持可见。
- **FR-5.6** 所有行的轨道必须使用同一个时刻到横坐标的映射，使同一时刻在各行处于同一横坐标。
- **FR-5.7** 轨道由等宽的格组成。格宽等于轨道可用宽度除以格数，但不得小于 24 像素；格宽达到下限时，编辑区出现水平滚动条。
- **FR-5.8** 轨道上的每个格都必须画成带框线的格子：格与格之间的竖线、行与行之间的横线，在每种行的底色上都清晰可见；整点处的竖线更粗。轨道两端不留白，第一个格和最后一个格紧贴轨道两端。
- **FR-5.9** 时间标尺只在整点处标注时刻，格式为 H:MM，例如 8:00；显示范围的起点或终点是半点时，那里不标注。整点标注都在同一行，以它的边界线为中心；恰好在轨道两端的整点标注例外，分别左对齐、右对齐到边界线，使它完整显示在轨道之内。

### 5.3 模板页

- **FR-5.3** 模板页的编辑区自上而下依次为：
  - 时间标尺；
  - 唯一模板区：只有唯一模板一行；
  - 周模板区：七个周模板行，从一周起始日开始按星期排列。
- **FR-5.10** 唯一模板与周模板不在同一个抽象级，界面上必须一眼可分，而且要看得出唯一模板是**高一层的图层**：
  - 唯一模板区（连同它的层级标题）显示为浮在周模板区上面的一层：底色更亮，下沿有投影；
  - 周模板区是下面一层，底色比唯一模板区暗一档；编辑区滚动时，周模板区从唯一模板区下面经过，被它遮住；
  - 两个区分别带有层级标题（“唯一模板”“周模板”），行高不同；
  - 这些区别在灰度下仍可分辨。
- **FR-5.21** 唯一模板区默认可见，可以折叠隐藏；隐藏时周模板区仍可编辑。唯一模板区可见时，它和时间标尺一起固定在编辑区顶部。
- **FR-5.22** 模板页中唯一模板行和七个周模板行都是可编辑行。

### 5.4 日程页

- **FR-5.23** 日程页按加载范围列出全部具体日子，按周分组、日期正序。每组有组标题，写明这一周的起止日期。
- **FR-5.24** 日程页的参照行都和时间标尺一起固定在编辑区顶部，并同 FR-5.10 显示为浮在上面的一层：
  - 唯一模板参照行只有一个，始终显示；
  - 周模板参照行不逐天显示。没有选区时，一个周模板参照行也不显示；选中某个具体日子行上的格或区间后（设这一天是星期 x），在唯一模板参照行的下方显示且只显示星期 x 的周模板参照行；选区清空时它随之消失。选区跨多行时，按锚点所在行（区间选区按主区间所在行）的星期；
  - 周模板参照行出现、消失或换成别的星期时，下面的具体日子行在屏幕上的位置应当保持不动（编辑区的滚动位置相应调整），刚单击的行不跳开；
  - 两种参照行默认可见，可以分别隐藏。
- **FR-5.32** 日程页必须看得出三层：唯一模板（第一级）、周模板（第二级）、具体日子（第三级）。
  - 两个参照行同在一张浮起的卡片上（FR-5.10），中间以一条细线分开；卡片下沿有投影，具体日子行从它下面经过；
  - 底色逐级变暗：唯一模板参照行最亮，周模板参照行次之，具体日子行和分组标题最暗；
  - 行头左侧有一条层级竖条，第一级颜色最深，第二级较浅，第三级不画；行名逐级向右缩进。不用数字编号；
  - 参照行不比具体日子行矮：唯一模板参照行最高，周模板参照行次之；
  - 以上区别在灰度下仍可分辨。
- **FR-5.25** 参照行是只读的：
  - 在参照行上的鼠标操作和键盘操作都不生效；
  - 键盘导航跳过参照行；
  - 参照行与具体日子行必须一眼可分，且在灰度下仍可分辨。
- **FR-5.26** 一屏显示多少天由编辑区的高度决定，其余日子滚动查看。打开日程页时，必须滚动到当前日期所在的周。当前日期的行头必须另外标出“今天”。
- **FR-5.27** 具体日子行的行名格式为“9月29日 周二”。

### 5.5 区间的显示

- **FR-5.11** 区间显示为覆盖其全部格的横条，横条上显示时长（按 FR-4.6）和文字，时长在前。空间不够时见 FR-5.15。
- **FR-5.12** 外部固定安排的文字必须显示在圆角边框之内，对应手绘图中的圈注；自主安排和日常事务的文字不加边框。三种横条的形状也必须不同：
  - 外部固定安排：实心块；
  - 自主安排：浅底加描边；
  - 日常事务：半透明浅底，没有描边，格线透过横条可见。
- **FR-5.13** 浮动区间的横条边框必须为虚线。浮动区间在时长后显示它的文字；文字为空时显示“浮动”二字。
- **FR-5.14** 首尾相接的两个区间之间必须有可见的分隔，使用户能区分它们。
- **FR-5.15** 横条优先显示文字（文字为空的浮动区间，文字处为“浮动”）：宽度放得下完整的文字和时长时两者都显示；放不下时整个隐藏时长，只显示文字；文字单独一行也放不下时，折成两行；两行仍放不下时，截断并以省略号表示。参照行同样如此。没有文字的横条只显示时长，放不下时截断。鼠标悬停时必须显示完整内容，格式为“周二，18:30–21:00，2.5h，外部固定安排，活动，浮动”；具体日子以“9月29日 周二”代替“周二”。
- **FR-5.16** 以上各项区别（类别、浮动、选中状态）必须在不依赖颜色的情况下可以分辨，见 NFR-3。
- **FR-5.29** 时刻事件显示为该时刻处的一条半透明的蜂蜜黄粗竖线（压在横条上时能透出横条的颜色），贯穿整行高度，粗细处处相同：恰在轨道两端时整条收在轨道之内，不被行头遮住一半；画在区间横条之上；文字写在竖线顶端旁边的小标签里，默认在竖线右侧，靠近轨道右端时在左侧。竖线和标签都可以与横条、轨道边缘、其他时刻事件重叠。参照行同样显示。鼠标悬停在标签上时显示“周一，07:00，起床（时刻事件，在文本中修改）”；起床、就寝沿用上级时注明来源，如“周一，07:00，起床（沿用唯一模板，时刻事件，在文本中修改）”。
- **FR-5.31** 清醒时段：有效起床时刻（3.5 节）存在的行，轨道上从显示范围起点到起床时刻铺暗色；有效就寝时刻存在的行，从就寝时刻到显示范围终点铺暗色。暗色铺在横条之下，横条照常显示；灰度下仍可分辨。起床、就寝的竖线比其他时刻事件更粗。参照行同样显示。
- **FR-5.30** 时刻事件不能选中：在它上面单击、拖动，效果与在它下面的格或区间上相同；键盘导航也跳过它。

### 5.6 选区的显示

- **FR-5.17** 格选区显示为所选格的框线加粗并改为铜色，可另加很淡的铜色底；区间选区显示为所选区间外侧的加粗边框。两种显示方式必须不同。格选区的锚点格不另画框：选区内其余的格有淡底，锚点格没有，以此标出锚点（与电子表格相同）。
- **FR-5.18** 编辑区下方必须有一个状态栏，显示当前选区的描述和最近一次操作的结果或错误信息。
  - 格选区的描述格式为“周二、周四，18:30–21:00，2.5h”；
  - 区间选区的描述格式同 FR-5.15。

### 5.7 笔记区（已取消）

- **FR-5.19** 已取消。原为：笔记区位于编辑区下方，是一个多行文本输入框。现在页面上不显示笔记，笔记在文本视图中修改（术语“笔记”、FR-7.2）；笔记内容仍原样保存，工具不解析它。

### 5.8 文本视图

- **FR-5.20** 文本视图是一个位于页面右侧的面板，由顶栏的“文本视图”按钮显示或隐藏，默认隐藏。面板包含一个多行文本框和“应用”“放弃修改”“复制”三个按钮，行为见第 7 节。

### 5.9 文档设置

- **FR-5.28** “文档设置”对话框用于修改显示范围、一周起始日和起始日。
  - 时刻和星期用下拉框选择；
  - 日期用三个下拉框（年、月、日）或等效的不依赖系统区域设置的控件选择，不得使用系统日期控件（见 NFR-5）；
  - 修改不合法时对话框保持打开，并说明原因。

## 6 交互操作

交互以格为对象，方式类似电子表格：用户先选中格或区间，再对选区执行操作。任一时刻，选区处于三种状态之一：空、格选区、区间选区。选区只包含当前页的可编辑行；切换页面时选区变为空。

### 6.1 鼠标选择

- **FR-6.1** 单击一个格时：
  - 如果该格在当前的格选区之内，选区变为空（再次单击取消选区）；
  - 否则，如果该格属于某个区间，选区变为只含该区间的区间选区；
  - 否则选区变为只含该格的格选区。

  单击的格成为锚点。
- **FR-6.2** 在任一格上按下鼠标并拖动，指针越过至少一条格边界后，选区变为格选区：
  - 行集合为按下所在行与指针所在行之间（按显示顺序，含两端）的全部可编辑行；
  - 时间段为按下所在格与指针所在格之间（含两端）的连续格；
  - 拖动过程中必须实时显示选区。
- **FR-6.3** 按住 Shift 单击一个格时，选区变为以锚点和该格为对角的矩形格选区，锚点不变。
- **FR-6.4** 应当支持按住 Ctrl 单击行头，把该行加入或移出当前格选区的行集合，时间段不变。被选中的行可以不相邻。
- **FR-6.5** 应当支持按住 Ctrl 单击区间，把该区间加入或移出当前区间选区。
- **FR-6.6** 应当支持在已选中区间的左右边缘 6 像素以内按下并拖动，以调整该区间对应的端点。
  - 这是移动类操作，端点按格对齐，冲突时按 FR-4.5 处理；
  - 区间长度不得小于 1 格。
- **FR-6.7** 双击区间时进入该区间的文字编辑，见 FR-6.12。
- **FR-6.8** 单击编辑区中可编辑行轨道以外的位置，单击编辑区之外的任何位置（上下文菜单、行菜单、对话框和显示设置面板除外），或按 Esc，选区变为空。
- **FR-6.9** 右键单击时，如果位置不在当前选区内，先按 FR-6.1 选中，再弹出上下文菜单。菜单列出当前选区可用的全部操作及其快捷键。

### 6.2 键盘操作

快捷键只在焦点位于编辑区时生效，焦点位于标题、文本视图或任何输入框时不生效。
- “上方”“下方”“相邻行”一律指当前页中相邻的可编辑行，跳过参照行和分组标题。
- “写入”与“移动”两栏分别表示该操作属于写入类操作（按 FR-4.4 覆盖处理）或移动类操作（按 FR-4.5 拒绝处理）。

| 按键 | 格选区时的行为 | 区间选区时的行为 | 类型 |
| --- | --- | --- | --- |
| E | 在选区的每一行创建一个覆盖选中时间段的外部固定安排区间，随后进入文字编辑 | 把所选区间的类别改为外部固定安排 | 写入 |
| S | 在选区的每一行创建一个覆盖选中时间段的自主安排区间 | 把所选区间的类别改为自主安排 | 写入 |
| D | 在选区的每一行创建一个覆盖选中时间段的日常事务区间，随后进入文字编辑 | 把所选区间的类别改为日常事务 | 写入 |
| F | 不生效，状态栏提示先选中区间 | 切换所选区间的浮动属性；所选区间的浮动属性不一致时全部设为 true | — |
| Enter | 不生效 | 进入文字编辑 | — |
| Space | 选中锚点格所在的区间 | 不生效 | — |
| Delete 或 Backspace | 清除选中的格，已有区间按 FR-4.4 删除或截断 | 删除所选区间 | 写入 |
| ← → | 选区变为锚点左侧或右侧相邻的单个格 | 所选区间整体平移一格 | 移动 |
| Shift + ← → | 向左或向右扩展格选区的时间段一格 | 所选区间的结束端点移动一格 | 移动 |
| Ctrl + ← → | 不生效 | 所选区间的开始端点移动一格 | 移动 |
| ↑ ↓ | 选区变为锚点上方或下方相邻行的同一格 | 选区变为上方或下方相邻行中、与所选区间时间段相同的格选区 | — |
| Shift + ↑ ↓ | 向上或向下扩展格选区的行集合一行 | 不生效 | — |
| Alt + ↑ ↓ | 不生效 | 把所选区间移到上方或下方相邻行的同一时间段 | 移动 |
| Tab、Shift + Tab | 不生效 | 选中同一行中的下一个或上一个区间，行尾时转到下一行 | — |
| Ctrl + C | 复制选区，见 6.4 | 复制所选区间，见 6.4 | — |
| Ctrl + X | 复制后清除选区 | 复制后删除所选区间 | 写入 |
| Ctrl + V | 粘贴，见 6.4 | 粘贴，见 6.4 | 写入 |
| Ctrl + Z | 撤销 | 撤销 | — |
| Ctrl + Shift + Z 或 Ctrl + Y | 重做 | 重做 | — |
| Ctrl + S | 立即把尚未写入的修改写入计划文件（FR-7.14） | 同左 | — |
| Alt + 1、Alt + 2 | 切换到模板页、日程页 | 切换到模板页、日程页 | — |
| Esc | 清空选区 | 清空选区 | — |

- **FR-6.10** 表中所列的行为均为必须实现，Tab 和 Shift + Tab 除外，二者为应当实现。
- **FR-6.11** 当区间选区含多个区间时，平移、调整端点、跨行移动作用于每一个所选区间；只要其中任何一个产生冲突，整个操作按 FR-4.2 不生效。

### 6.3 文字编辑

- **FR-6.12** 进入文字编辑时，区间上方出现一个单行输入框，内容为区间当前的文字（多个区间文字不一致时为空）。Enter 确认，把文字写入全部所选区间；Esc 取消，数据不变。
- **FR-6.13** 确认时如果文字违反 3.3 节的约束，必须不生效，输入框保持打开，并在状态栏说明违反的约束。

### 6.4 复制与粘贴

- **FR-6.14** 复制的内容是一个矩形：高度为行数，宽度为时间段长度。
  - 其中每一行记录与该时间段相交的区间，区间被截取到时间段之内，位置以相对于时间段起点的偏移量记录。
  - 复制格选区时，矩形即选区本身。
  - 复制区间选区时，矩形的行集合为所选区间所在的行，时间段为从最早开始到最晚结束的范围。
- **FR-6.15** 粘贴的锚点是：
  - 当前为格选区时，是它的左上格；
  - 当前为区间选区时，是位于最上面一行、开始最早的那个区间的起点。

  矩形的第 k 行粘贴到锚点行之下第 k 个可编辑行，时间段起点与锚点对齐。复制与粘贴可以跨页进行。
- **FR-6.16** 粘贴是写入类操作：目标矩形覆盖的全部格先按 FR-4.4 清除，再放入复制的区间。矩形中没有区间的部分也会被清除。
- **FR-6.17** 如果粘贴的矩形超出当前页的最后一个可编辑行或超出显示范围，粘贴必须整体不生效，并在状态栏说明原因。
- **FR-6.18** 可以同时把复制内容以第 7 节的区间行格式写入系统剪贴板，便于粘贴到其他文本中。

### 6.5 行操作

- **FR-6.19** 每个可编辑行的行头必须提供一个菜单，由行头上的按钮或右键行头打开。
  - 周模板和具体日子的菜单包含：“重置为模板”（FR-4.12，跟随状态下不可用）、“清空此行”、“选中整行”。
  - 唯一模板的菜单包含：“清空此行”、“选中整行”。
  - “清空此行”使该安排对象变为已编辑且没有区间；它的时刻事件保留（时刻事件只在文本中修改）。
- **FR-6.20** （已取消。原为“新建一周”执行前的确认；“新建一周”已由继承规则取代。）

### 6.6 撤销与重做

- **FR-6.21** 所有改变计划文档的操作都必须可以撤销和重做，包括标题、文档设置的修改，以及在文本视图中应用的修改（笔记只能这样修改）。撤销历史至少保留 200 步。选区的变化和页面切换不计入撤销历史。
- **FR-6.22** 标题中的连续输入应当合并为一个撤销步骤，在输入框失去焦点或停止输入 1 秒后结束该步骤。
- **FR-6.23** 执行新操作后，重做历史必须清空。

## 7 文本格式与文件读写

计划文档与一种 md 文本格式一一对应。工具写出的文本称为规范文本；工具读入时接受比规范文本更宽松的写法，但读入结果再写出时必须得到规范文本。

### 7.1 文法

```
文档       = 标题行 空行* 设置行{3} 空行* 唯一模板节 周模板节* 日子节* 笔记节
标题行     = "# " 标题
设置行     = 范围行 | 周起始行 | 起始日行            ; 三种各一行
范围行     = "范围 " 时刻 "-" 时刻
周起始行   = "一周起始 " 星期名
起始日行   = "起始日 " 日期
唯一模板节 = "## 唯一模板" 换行 区间块
周模板节   = "## " 星期名 换行 区间块                ; 只写已编辑的周模板
日子节     = "## " 日期 " " 星期名 换行 区间块       ; 只写已编辑的具体日子
笔记节     = "## 笔记" 换行 任意文本                  ; 必须是最后一节
区间块     = 空行* ( ( 区间行 | 事件行 ) 空行* )*
区间行     = 时刻 "-" 时刻 [ 空格 文字部分 ]          ; 不浮动的区间
           | 时刻 "-" 时刻 空格 "~" 浮动文字部分      ; 浮动的区间
文字部分   = "[" 文字? "]"                           ; 外部固定安排
           | "(" 文字? ")"                           ; 日常事务
           | 文字                                     ; 自主安排
浮动文字部分 = "[" 文字? "]"                         ; 外部固定安排
           | "(" 文字? ")"                           ; 日常事务
           | "浮动"                                   ; 自主安排，文字为空
           | 文字                                     ; 自主安排
事件行     = 时刻 空格 文字                           ; 时刻事件，例如 "07:00 起床"
时刻       = 时 ":" ( "00" | "30" )                   ; 时为 0 至 24，24 只允许为 "24:00"
星期名     = "周日" | "周一" | "周二" | "周三" | "周四" | "周五" | "周六"
日期       = 四位年 "-" 两位月 "-" 两位日
```

只有一个时刻、后面直接跟文字的行是时刻事件，例如“07:00 起床”“23:00 睡觉”。

方括号对应手绘图中的圈注。外部固定安排可以没有文字，此时写作“\[\]”。圆括号表示日常事务，例如“12:00-13:00 (吃饭)”，没有文字时写作“()”。

“~”表示浮动，浮动区间的文字写在“~”后面，也就是它在界面上显示的文字：“18:30-20:30 ~浮动”显示“浮动”，“18:30-20:30 ~读书”显示“读书”，“18:30-20:30 ~\[上课\]”是浮动的外部固定安排，“18:30-20:30 ~(吃饭)”是浮动的日常事务。

文件里写出来的周模板和具体日子就是已编辑的，没写出来的就是跟随的。已编辑但没有区间的安排对象，只写小节头，不写区间行。

### 7.2 解析规则

- **FR-7.1** 各节的顺序和出现次数必须满足以下规定，缺少、重复或顺序错误都是错误：
  - 唯一模板节和笔记节各出现一次；
  - 每个星期的周模板节至多出现一次；
  - 每个日期的日子节至多出现一次，日子节中的星期名必须与日期相符；
  - 顺序为：唯一模板节、周模板节、日子节、笔记节。周模板节之间、日子节之间的先后不限。
- **FR-7.2** “## 笔记”之后直到文件末尾的全部文本原样作为笔记内容，其中以“#”开头的行也不再解析。笔记内容首尾的空行被去除。
- **FR-7.3** 读入时接受以下宽松写法：
  - 时刻中的时可以写一位或两位数字（8:00 与 08:00 等价）；
  - 连字符两侧可以有空格，“-”也可以写作“–”；
  - 行首行尾的空格被忽略；
  - 区间行在同一节内可以不按时间顺序书写；
  - “~”也可以写作全角“～”；“~”前面的空格可以省略，后面可以有空格；
  - 文字为空的浮动自主安排可以只写“~”，与“~浮动”相同；
  - 日常事务的圆括号也可以写作全角“（”“）”，写出时一律用半角；
  - 三种设置行的先后不限。
- **FR-7.4** 每个区间必须满足 3.3 节的约束和 I-1 至 I-3，每个时刻事件必须满足 3.5 节的约束，否则是错误。
- **FR-7.5** 解析必须找出文本中的全部错误，而不是在第一个错误处停止。每条错误信息必须包含行号和原因，例如“第 14 行：09:30-12:30 与第 13 行的 08:00-10:00 重叠”。
- **FR-7.6** 只要存在任何错误，解析结果必须整体不生效，计划文档保持不变。
- **FR-7.19** 读入时必须兼容修订前的格式，并按新格式写出：
  - 标题“## 模板”视为“## 唯一模板”；
  - 七个“## 周一”至“## 周日”视为七个已编辑的周模板；
  - 缺少周起始行时取周日；
  - 缺少起始日行时取当前日期所在周的第一天；
  - 浮动标记写在行尾的“文字部分 ~浮动”（例如“18:30-20:30 读书 ~浮动”“08:00-12:00 \[上课\] ~浮动”）读作浮动区间，文字取“~浮动”前面的部分，写出时改为“~读书”“~\[上课\]”。其他把文字写在“~”前面的写法是错误。

### 7.3 规范文本

- **FR-7.7** 规范文本满足以下规定：
  - 使用 UTF-8 编码和 LF 换行，以一个换行结尾；
  - 时刻一律写作两位小时，例如 08:00；
  - 设置行依次为范围行、周起始行、起始日行；
  - 周模板节按从一周起始日开始的星期顺序排列，日子节按日期升序排列；
  - 小节之间恰好空一行；每节内的区间行和事件行按时刻升序排列（区间按 start），同一时刻事件行在前；同一时刻的多个事件行保持原有先后。
- **FR-7.8** 对任意合法的计划文档 d，解析 d 的规范文本得到的计划文档必须与 d 相同（区间 id 除外），包括时刻事件。

### 7.5 文本视图

- **FR-7.9** 文本视图没有未应用的修改时，其内容必须始终等于当前计划文档的规范文本，并随图形编辑实时更新。
- **FR-7.10** 用户在文本视图中输入后，文本视图进入“有未应用修改”状态。
  - 在此状态下，编辑区和标题必须为只读，并显示提示；
  - 直到用户点击“应用”并成功，或点击“放弃修改”，才恢复可编辑；
  - 这一规定避免两处同时修改造成冲突。
- **FR-7.11** 点击“应用”时按 7.2 节解析。
  - 成功时，计划文档替换为解析结果，作为一个撤销步骤，文本视图退出“有未应用修改”状态；
  - 失败时，在文本框下方列出全部错误，计划文档不变。
- **FR-7.12** 点击“放弃修改”时，文本视图的内容恢复为当前计划文档的规范文本。

### 7.6 文件读写

工具只编辑一个计划文件，由服务读写。页面不再使用浏览器的文件接口和本地存储保存计划文档。

- **FR-7.13** 计划文件的位置：
  - 默认为工具设置目录中的 `plan.md`。设置目录平常在 `%APPDATA%\weekline\`；工具目录中有 `portable` 文件时就是工具目录（便携模式，web-kit `tooldirs`）。
  - 可以在设置目录的 `settings.json` 中用 `plan_file` 指定别的路径，例如放进同步盘。
  - 页面打开时，服务读入计划文件并按 7.2 节解析。文件不存在时，以 7.4 节的示例新建（起始日取当前日期所在周的第一天）并写入。
  - 解析失败时，服务不得改写该文件；页面打开文本视图，显示文件内容和全部错误。用户在文本视图中修改并应用成功后，才写入计划文件。
  - 读入修订前格式的文件（FR-7.19）时，只在第一次修改后才以新格式写回，只打开不改写。
- **FR-7.14** 自动保存：计划文档每次被修改后，工具必须在 1 秒内把规范文本写入计划文件，不需要用户操作。
  - 写入必须是原子的：先写临时文件再替换，写到一半中断不会留下不完整的文件；
  - 写入失败时，修改保留在页面中，顶栏按 FR-5.2 提示；服务恢复后，工具必须自动重试，直到写入成功；
  - Ctrl + S 立即写入，不等待。
- **FR-7.15** 外部修改：计划文件可能在工具之外被修改（例如用文本编辑器）。
  - 服务在每次写入前必须确认，文件自工具上次读写以来没有被别处修改；被修改过时，不得写入。
  - 页面重新获得焦点时，必须检查计划文件是否在别处被修改。被修改过、而页面没有尚未写入的修改时，自动载入文件的新内容，作为一个撤销步骤，并在状态栏说明。
  - 两边都有修改时，顶栏按 FR-5.2 显示“文件在别处被修改”，并让用户二选一：“载入文件的版本”（页面的修改可以撤销找回）或“用本页的内容覆盖文件”。
  - 载入的内容解析失败时，按 FR-7.13 的解析失败处理。
- **FR-7.16** “导入”让用户选择一个 .md 或 .txt 文件并按 7.2 节解析。
  - 成功时，计划文档替换为解析结果，作为一个撤销步骤，随后按 FR-7.14 写入计划文件；
  - 失败时计划文档不变，文本视图打开并显示该文件的内容和全部错误，便于用户修改后应用。
- **FR-7.17** “导出”以“标题.md”为文件名，下载当前计划文档的规范文本。
- **FR-7.18** 有尚未写入计划文件的修改，或文本视图中有未应用的修改时，用户关闭或刷新页面前，工具必须请求浏览器显示离开确认。
- **FR-7.20** 服务应当在每天第一次写入计划文件之前，把原文件复制一份到数据目录的 `backup/`，文件名带日期，保留最近 30 份。

## 8 非功能需求

- **NFR-1** 工具是本机网页服务加页面，与使用 web-kit 的其他工具同构：
  - 服务用 Python 3.8 或以上版本写成，只用标准库；页面只用浏览器原生的 HTML、CSS、JS，没有构建步骤。
  - 服务只监听 127.0.0.1，不需要网络连接。服务与页面之间的安全措施用 web-kit 的做法：校验 Host 头；写操作要求自定义请求头并校验 Origin。
  - 双击工具目录中的启动脚本即可使用：启动服务并打开浏览器。Python 解释器由 web-kit 的 `find-python.ps1` 查找，不写死路径。
  - 发布包自带免安装版 Python（web-kit 的 `pack.py`），解压后不需要另装 Python。
  - 工具目录中带一份 web-kit 的副本，来历记在 `vendor.json`，副本不改。
- **NFR-2** 工具运行于 Windows 10 和 Windows 11。页面必须在当前版本的 Chrome、Edge 和 Firefox 桌面版上完整可用。
- **NFR-3** 以下各项必须在灰度显示下仍可分辨，即不能只靠颜色区分：
  - 区间的类别、浮动与否、选中状态；
  - 格选区与区间选区；
  - 唯一模板区与周模板区；
  - 参照行与具体日子行；
  - 跟随状态与已编辑状态。

  正文文字与背景的对比度必须不低于 4.5:1。
- **NFR-4** 所有功能都必须可以只用键盘完成，文件选择对话框除外。
- **NFR-5** 界面文字为中文。时刻与日期的显示和输入一律采用 24 小时制和 YYYY-MM-DD 或“9月29日”的写法，不受操作系统区域设置的影响；工具不得使用会按区域设置显示的系统时间或日期输入控件。
- **NFR-6** 配色必须采用配色约定第 4 节的四套配色（深青、青瓷、暖炭、象牙），并遵守其纪律：
  - 铜色只用于重点与选中；
  - 时刻事件的竖线和标签用半透明的蜂蜜黄（FR-5.29）。它和类别色一样是本工具自己的颜色，按浅色、深色两组给出取值，不属于配色约定；
  - 琥珀色只用于提醒，例如只读、文件在别处被修改；
  - 绛红色只用于错误，例如保存失败；
  - 三种区间各用一种类别色：外部固定安排蓝（冷），自主安排沙（暖），日常事务浅绿、半透明。类别色是本工具自己的样式，由本工具的样式表按四套配色分别给出取值，不属于配色约定，也不取自 web-kit。类别色只标类别，不得用于区间以外的地方。颜色之外，三种区间的横条还必须有形状上的区别（FR-5.12），满足 NFR-3。

  配色的切换用 web-kit 的显示设置（界面约定第 3 节“显示设置”）：
  - “显示设置”面板可以选四套配色，并调英文字体、英文粗细、灰字亮度；
  - 顶栏的深浅切换按钮在同一对之间切换：深青↔青瓷，暖炭↔象牙；
  - 取值分三层：当前值存在浏览器中；“设为默认”存到工具数据目录的 `ui_prefs.json`；出厂值。显示设置不写入计划文档。
  - 本工具的出厂配色为**象牙**，其余出厂值与界面约定相同。

  四套配色都必须满足 NFR-3。
- **NFR-7** 在显示范围为 48 格、加载范围为 90 天的计划文档上，任何单个操作从按键或松开鼠标到界面更新完成，必须不超过 50 毫秒。
- **NFR-8** 任何会删除内容的操作都必须可以撤销，或在执行前经过用户确认。工具不得在没有撤销或确认的情况下丢失数据。
- **NFR-9** 数据模型、继承、规则校验、日期计算、文本解析与序列化必须与界面渲染分离，并以不依赖浏览器界面的纯函数实现，以便单独测试第 4 节和第 7 节的规则。日期计算必须以当前日期为参数传入，不得在纯函数内部读取系统时间。这些纯函数在页面中运行；服务只负责读写计划文件，不解析计划文档的内容。
- **NFR-10** 后台运行（界面约定第 3 节“后台运行，不留无用的窗口”）：
  - 启动脚本用 `pythonw` 拉起服务后立即返回，不留控制台窗口；
  - 服务的输出写到数据目录的日志文件；启动失败（例如端口被占）必须弹出系统对话框说明原因；
  - 服务已在运行时，再次双击启动脚本只打开浏览器；
  - 提供停止服务的命令行参数 `--stop`；
  - 页面打开时每分钟向服务报到一次；连续 30 分钟没有任何请求、且没有尚未完成的写入时，服务自动退出。
- **NFR-11** 本机显示参数（界面约定第 3 节“本机硬件参数”）：服务向 Windows 读取各显示器的分辨率和系统缩放，页面据此：
  - 在浏览器缩放不是 100% 时，在状态栏提示按 Ctrl + 0 复原；
  - 在高分辨率配低系统缩放时整体放大界面。

  做法用 web-kit，测试用本机的真实参数。
- **NFR-12** 字体、字号与形状遵守界面约定第 3 节：
  - 字体为显示设置所选的英文字体加微软雅黑 UI；界面文字 13px，次要文字 12px，页标题 16px；
  - 只有页标题加粗（600），中文不加粗，强调靠颜色；
  - 时刻、时长、日期等数值用等宽数字；
  - 面板、按钮、菜单、对话框的圆角为 2–4px，描边 1px，不用阴影；分隔线用 `line2`。

  例外：区间横条的边框为 1.5–2px（虚线在 1px 下难以辨认，FR-5.13），选区的外框更粗（FR-5.17）。二者是数据标记，不是面板描边。另一个例外是唯一模板区（以及日程页顶部的唯一模板参照行）下沿的投影：它表示这一层在周模板之上（FR-5.10），是图层关系的标记，不是面板装饰。

## 10 不在范围内的内容与待定事项

### 10.1 不在本版本范围内的内容

以下内容在需求讨论中被排除，或没有依据，本版本不实现。
- 统计与评价，包括每日或每周的时长合计、与模板的差值、最长连续时段、每日最高工作时长的检查。这些计划判断保留在笔记中。
- 活动-休止结构的内部组成，以及某一部分归属于哪个结构。区间作为已包装的结构整体处理。
- 多个唯一模板，或多套周模板（例如单双周）。
- 实际执行情况的记录，以及计划与实际的对比。具体日子只表示那一天的计划。
- 加载范围之外的日子（更远的将来）的编辑。
- 手机和平板上的使用；Windows 以外的操作系统。
- 管理多个计划文件（列表、切换）。工具只编辑一个计划文件，要换文件时改 `settings.json` 中的 `plan_file`，或使用导入、导出。
- 多人协作和在线同步。

### 10.2 待定事项

以下各项在本文档中已给出暂定规定，需要确认后定稿。
- **Q-1** 写入类操作采用覆盖处理（FR-4.4），即选中已有区间所在的格后设为区间，会删除或截断原有区间。另一种做法是拒绝，要求用户先清除。本文档暂定为覆盖。
- **Q-2** 外部固定安排是否必须带文字。本文档暂定为可以不带文字，写作“\[\]”。
- **Q-3** （已定）显示范围可以修改，入口为“文档设置”（FR-5.28）。
- **Q-4** 浮动是否需要任何行为，例如在某一天标记为“已取消”。本文档暂定为只显示、无行为。
- **Q-5** 7.4 节示例中，手绘图没有画出的时段填入了唯一模板的区间。这是否符合手绘图的原意，需要确认；它只影响示例和 AC-10 的内容，不影响其他需求。
- **Q-6** 已编辑的下级在上级改变后是否需要提示（例如行头标出“上级已改动”）。本文档暂定为不提示。
- **Q-7** 参照行是否允许选中和复制（只读但可复制）。本文档暂定为完全不可操作。
